À propos

Un site statique de quelques fichiers, hébergé par GitHub Pages. Pas de serveur, pas de base de données, pas d'étape de compilation.

Modifier le site

Chaque page est un fichier HTML complet. Pour changer un texte, on ouvre le fichier, on édite, on enregistre — depuis GitHub dans un navigateur mobile, l'application GitHub, ou n'importe quel éditeur.

Pour ajouter une page : dupliquer un fichier existant, changer le titre et le contenu, puis ajouter le lien dans le bloc <nav> des quatre pages. Le lien de la page courante est mis en évidence automatiquement.

Publication

Un push ne met rien en ligne. La publication se déclenche à la main, depuis Actions › Deploy to GitHub Pages › Run workflow : commiter et publier sont deux gestes séparés. Le fichier .nojekyll évite que Jekyll ne retraite les fichiers au passage.

Une seule manipulation a été nécessaire au départ : Settings › Pages › Source › GitHub Actions — le jeton des workflows n'a pas le droit de créer le site lui-même.

Prévisualiser avant de publier

Le menu Run workflow permet de choisir la branche à publier. Lancer la branche par défaut met à jour le site à la racine ; lancer n'importe quelle autre branche la publie sur /preview/<nom-de-la-branche>/, la racine restant inchangée.

Depuis un téléphone : éditer un fichier, choisir Create a new branch au moment de valider, lancer le workflow sur cette branche, puis la fusionner quand le résultat convient. La racine du site est toujours reconstruite depuis la branche par défaut : une preview ne peut pas abîmer le site en ligne.

Accessibilité et performance

  • Toutes les images ont un texte alternatif et des dimensions déclarées.
  • Les cibles tactiles font au moins 44 px de haut.
  • Le thème clair ou sombre suit le réglage du téléphone.
  • Le site entier pèse moins de 100 ko, images comprises.
